# 治理与错误码

本文档定义“主线治理口径”：日志字段、错误码、超时/取消/排队语义，以及 metrics/admin status 的统计口径。

## 1. 日志建议统一字段（主线）

- `request_id`
- `api`
- `model`
- `backend`
- `capability`
- `session_id`
- `queue_wait_ms`
- `run_ms`
- `finish_reason`
- `status_code`
- `error_code`

排障时通常用 `request_id` 串起 `serving_http.log / unit_manager.log / node_test.log`（见：[`可观测性与排障.md`](可观测性与排障.md)）。

## 2. 主线错误码（统一口径）

输入与参数：

- `model_required`
- `invalid_input`
- `invalid_query`
- `invalid_documents`
- `invalid_top_n`

模型与能力：

- `model_not_found`
- `capability_not_supported`

后端与超时：

- `backend_not_available`
- `request_timeout`
- `backend_timeout`

取消与排队：

- `request_cancelled`
- `queue_full`
- `queue_timeout`

限流：

- `rate_limit_global`
- `rate_limit_model`
- `rate_limit_session`

其它：

- `internal_error`

## 3. Queue / Timeout 语义（主线心智）

- 同 `session_id` 的请求会串行执行，避免多轮历史并发污染。
- 之后按 `model + inference_backend`（路由 key）排队并复用引擎实例。
- `queue_wait_ms` 表示排队等待时间；超过上限会表现为 `queue_timeout` 或 overload 类错误。
- `request_timeout` 通常对应 HTTP 层整体超时；`backend_timeout` 通常对应后端推理超时（本地或 RPC）。

## 4. Admin Status / Metrics

以下接口会按统一口径累计 chat / embeddings / rerank 三条主线的错误、超时、取消、限流与 token（或近似 usage）统计：

- `/metrics`
- `/admin/models/status`
- `/admin/backends/status`

字段与案例建议直接看：[`API调用示例.md`](API调用示例.md) 中的 admin 示例与错误请求示例。
