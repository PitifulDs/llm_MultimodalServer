# 回调函数与事件流（从 onMessage 到回包）

本文档把项目里的“回调函数”按**注册点**与**触发时机**串起来，重点覆盖你在 `serving/http/NetworkHttpServer.cc` 里看到的 `onMessage()`：它究竟是谁回调的、在什么线程里调用、以及后续如何路由到业务并把响应写回 socket。

## 1. 回调分层总览

项目里最核心的回调链路分 3 层：

1) **网络层（Reactor）回调**：fd 可读/可写/关闭时触发  
2) **HTTP 适配层回调**：`TcpServer` 的 connection/message callback -> `NetworkHttpServer::{onConnection,onMessage}`  
3) **业务层回调**：断连 on_close、SSE chunk 回调、超时/取消 watchdog 等

## 2. 网络层：谁调用了 onMessage？

### 2.1 Channel 回调（fd 事件）

注册位置：`network/src/TcpConnection.cc`（构造函数）

- `channel_->setReadCallback(std::bind(&TcpConnection::handleRead, this))`
- `channel_->setWriteCallback(std::bind(&TcpConnection::handleWrite, this))`
- `channel_->setCloseCallback(std::bind(&TcpConnection::handleClose, this))`
- `channel_->setErrorCallback(std::bind(&TcpConnection::handleError, this))`

触发时机：

- Reactor 事件循环检测到 fd readable -> 调用 `handleRead()`

### 2.2 TcpConnection::handleRead -> messageCallback_

调用位置：`network/src/TcpConnection.cc` 的 `TcpConnection::handleRead()`

- 从 socket 读入 `inputBuffer_`
- `messageCallback_(shared_from_this(), &inputBuffer_)`

这里的 `messageCallback_` 由 `TcpServer` 设置（见下一节）。

### 2.3 TcpServer 把 messageCallback_ 设成 NetworkHttpServer::onMessage

注册位置：`serving/http/NetworkHttpServer.cc` 构造函数

- `server_.setConnectionCallback(std::bind(&NetworkHttpServer::onConnection, this, _1))`
- `server_.setMessageCallback(std::bind(&NetworkHttpServer::onMessage, this, _1, _2))`

`TcpServer` 在 `newConnection()` 时把 callback 下发到新连接：`network/src/TcpServer.cc`

- `conn->setConnectionCallback(connectionCallback_)`
- `conn->setMessageCallback(messageCallback_)`

因此实际调用栈（简化）是：

`Channel(readable)` -> `TcpConnection::handleRead()` -> `messageCallback_()` -> `NetworkHttpServer::onMessage()`

线程语义：

- 上述链路全部发生在**该连接所属的 EventLoop(IO) 线程**里（Reactor 线程）。

## 3. HTTP 适配层：onMessage 之后发生了什么？

### 3.1 onMessage：连接级 buffer 追加字节流

实现位置：`serving/http/NetworkHttpServer.cc`

- `cache.append(buf->retrieveAllAsString())`
- `handleHttpRequest(conn, cache)`

其中 `cache` 是 `http_buffers_[conn]`，按 `TcpConnectionPtr` 粒度维护。

### 3.2 handleHttpRequest：组包、解析、路由

实现位置：`serving/http/NetworkHttpServer.cc`

关键步骤：

- 找 `\r\n\r\n` 分隔 header/body
- 严格解析 `Content-Length`（POST 缺失 -> `411 Length Required`）
- 拒绝 `Transfer-Encoding: chunked`
- body 不足则 return（等待下一次 `onMessage` 继续收）
- body 收齐后构造 `NetworkHttpRequest req`
- stream 判定：body 的 `"stream": true` 优先；query `?stream=true` 仅兼容兜底
- 创建 `NetworkHttpResponse res_ptr`
- 按 URL 分发到 `HttpGateway::Handle*`

路由分发点：

- `dispatch_mainline_route(...)`
- `dispatch_compatibility_route(...)`

## 4. 回包：为什么 HttpResponse::Write 会“切回 IO 线程”？

### 4.1 NetworkHttpResponse::Write 的线程切换

实现位置：`serving/http/NetworkHttpTypes.h`（`NetworkHttpResponse`）

行为：

- 如果当前不在 `conn->getLoop()` 的 IO 线程：使用 `loop->queueInLoop([self, copy]{ self->WriteInLoop(copy); })`
- 如果已经在 IO 线程：直接 `WriteInLoop(data)`

这样做的目的：

- **保证最终的 `conn->send()` 在连接所属 IO 线程执行**
- 允许业务线程（例如 Serving 的 `ThreadPool`）安全地调用 `res.Write(...)`

### 4.2 非流式：WriteInLoop 里会自动 End()

`NetworkHttpResponse::WriteInLoop()` 对非 SSE（`sse=false`）的行为是：

- 首次写入前补齐 HTTP 响应行与 headers
- `conn->send(&buf)`
- 非 SSE：立即 `End()`（调用 `conn->shutdown()`）

SSE（`sse=true`）则保持连接不关闭，反复写入 chunk。

## 5. 断连回调：SetOnClose 是怎么被触发的？

### 5.1 SetOnClose：把回调塞进 TcpConnection::context_

接口：`serving/http/http_types.h` 的 `HttpResponse::SetOnClose(std::function<void()>)`

实现：`serving/http/NetworkHttpTypes.h` 的 `NetworkHttpResponse::SetOnClose(...)`

- `on_close_ = cb`
- `conn->setContext(on_close_)`（存到 `boost::any context_`）

### 5.2 onConnection：连接 down 时取出 context 并执行

实现：`serving/http/NetworkHttpServer.cc` 的 `onConnection()`

当 `!conn->connected()`：

- 清理 `http_buffers_`
- `boost::any_cast<std::function<void()>>(&ctx)` 取出回调并执行

线程语义：

- `TcpConnection::handleClose()` 会在 IO 线程触发 `connectionCallback_`（即 `onConnection`），因此 **on_close 也在 IO 线程执行**。

注意事项：

- `TcpConnection::context_` 是单槽位；如果多个模块同时想用 context，需要约定好存放结构（当前实现直接存 `std::function<void()>`）。

## 6. 业务层常见回调（chat/stream 为例）

### 6.1 非流式 chat：bind_on_close 注册取消逻辑

调用位置：`serving/http/HttpGateway.cc`

- `chat_service_->RunNonStream(..., bind_on_close, is_client_alive, ...)`
- `bind_on_close` 内部会调用 `res.SetOnClose(...)`

`ChatService` 会把 on_close 绑定为“客户端断开 -> cancelled -> EmitFinish(cancelled)”。

### 6.2 SSE chat：ctx->on_chunk 回调 -> OpenAIStreamWriter -> HttpStreamSession::Write

调用位置：`serving/http/HttpGateway.cc`

- `ctx->on_chunk = [writer, ctx](const StreamChunk& chunk){ writer->OnChunk(chunk); }`
- `OpenAIStreamWriter` 的输出回调里调用 `http_session->Write(s)`（最终走 `NetworkHttpResponse::Write` 切回 IO 线程）

流式模式的关键点是：

- **推理线程产生 delta**
- **写 socket 必须切回 IO 线程**（由 `NetworkHttpResponse::Write` 保证）
